# ytgrab 0.3.2

Fresh installs no longer stop at YouTube's "Sign in to confirm you're not a
bot" wall.

## What's fixed

- **YouTube cookies are arranged for you.** YouTube blocks many downloads that
  are not tied to a signed-in browser. ytgrab now reuses the cookies from a
  browser you are signed into YouTube with:
  - `setup.ps1` asks which browser that is and stores the answer.
  - With no explicit choice, ytgrab falls back to Firefox when it has a
    profile (the browser ytgrab runs in), so existing installs clear the wall
    without touching any config.
  - `cookies_from_browser` accepts `auto` (the default), `firefox`, `chrome`,
    `edge`, `brave`, ... or `none`. Change it any time with
    `ytgrab config cookies_from_browser <browser>`.

## New

- `ytgrab config` prints every stored setting, and `ytgrab config KEY VALUE`
  changes one. `setup.ps1` writes through it, so the config file has a single
  writer.

## How to get it

Run `ytgrab update`, or install this bundle. The extension updates itself.

## Under the hood

- `ytgrab_core.resolve_cookies_from_browser()` resolves an empty or `auto`
  value to Firefox only when a `cookies.sqlite` actually exists, so machines
  without a Firefox profile behave exactly as before; `none`/`off` disables
  cookies outright.
- The new `ytgrab config` subcommand is the supported way to read and write
  `~/.config/ytgrab/config.json`.
- `setup.ps1` gained a "YouTube sign-in (cookies)" step, between the helper and
  the browser extension.
