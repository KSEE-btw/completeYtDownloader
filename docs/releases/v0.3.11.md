# ytgrab 0.3.11

The queue becomes a real download manager: **several downloads at once**, full
pause/resume, reordering, and bulk actions.

## What's new

**Download more than one at a time.** Until now the queue drained strictly one
video at a time — with a fast connection that left the line idle while yt-dlp
finished remuxing. A picker at the top of the queue now sets how many run
together:

| Setting | Default | Range |
|---|---|---|
| `max_concurrent` | `2` | 1–8 |

The queue stays **first-in-first-out**: whatever the number, the earliest item
added is always the next one to start. (Fragments *within* a single file were
already downloaded in parallel via `concurrent_fragments`; this is about whole
videos.)

**Pause and resume.** A running download can now be **Paused** instead of only
cancelled — the part file is kept, so **Resume** carries on where it stopped
rather than starting the file over. Waiting items can be paused too, to hold
them back. **Pause all** / **Resume all** in the toolbar hold and release the
entire queue, which is handy before a call or a reboot. A paused item stays
paused across a restart.

**Reordering.** Waiting and paused items get **▲ ▼** buttons to move them up or
down the queue. Work already running keeps its slot; only the order of what is
waiting changes.

**Tick boxes and bulk actions.** Every row has a tick box on the left. Pick
several and **Cancel selected** / **Remove selected** act on the whole
selection at once; the buttons count what is picked.

**Shared colours and states.** Each new state has its own stripe colour —
paused is amber — and the item detail reads *"Paused — press Resume to carry
on"*.

## Notes

- `max_concurrent` is saved to your config when you change the picker, so the
  next window opens the same way. `ytgrab config max_concurrent 3` sets it from
  the command line too.
- Pausing during the download phase keeps the `.part` file; pausing during the
  final remux/conversion stops ffmpeg and re-runs that step on resume.
- Quitting with downloads in flight is unchanged: unfinished items resume next
  time you open the queue.
- No change to what gets downloaded or how it is converted — this release is
  all queue control.

## How to get it

Run `ytgrab update`, or install this bundle.
