# ytgrab 0.3.10

The audio marker in the format picker told the truth about the wrong thing. It
now describes **the file you get**.

## What was wrong

Since 0.3.7 every video format above 360p carried a 🔇 "no audio" marker, which
looked like a bug. It was not:

- YouTube muxes picture **and** sound into exactly one low "progressive" format
  — normally **360p**, sometimes also 720p.
- **Every other resolution is a video-only DASH stream**, with the sound in a
  separate audio track. Probing a 4K short film returns *one* video+audio
  format and 22 video-only ones.

So the data was right, but ytgrab has muxed the best audio back in since 0.3.3
(`ensure_audio`), which means the download was **never** silent. The marker
said "this stream has no audio" when the honest answer was "this download has
audio — we add it".

## What changed

The marker now answers the only question that matters: *will my file have sound?*

| Entry | Marker | Meaning |
|---|---|---|
| Video + audio (360p) | 🔊 | the stream already carries audio |
| Video only (1080p, 4K, …) | 🔊**+** | no audio of its own; ytgrab muxes the best audio in |
| Video only, `ensure_audio` off | 🔇 | genuinely silent |
| Audio only | *(none)* | an audio-only entry obviously has audio |

- The **"Video only" group is now labelled** *"Video only — ytgrab adds the best
  audio"* while muxing is on, so the icon cannot be misread.
- Hovering a format shows the real detail: *"vp9 — video-only stream; ytgrab
  muxes the best audio in"*.
- 🔇 now appears **only** when you have genuinely switched auto-muxing off, and
  then it is correct.

## Notes

- No change to downloads: `ensure_audio` still muxes as before. This is a
  display fix only.
- The marker follows your config, so toggling `ensure_audio` changes it on the
  next probe.

## How to get it

Run `ytgrab update`, or install this bundle.
