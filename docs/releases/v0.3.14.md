# ytgrab 0.3.14

A clip download now **shows its progress**. Before this the queue row sat at
**0%** for the whole clip and then jumped straight to done — it looked stuck,
even while it was working.

## What's fixed

**Clips report progress again.** A clip is cut with `--download-sections`, which
yt-dlp hands to ffmpeg whole; ffmpeg's position never reaches yt-dlp's progress
line, so a clip produced exactly one progress report — at the very end. ytgrab
now reads ffmpeg's own status line while it cuts, so the row counts up with a
percentage and an ETA.

**No more a stuck "0%".** While the download is still starting up
(reading the cookie store, resolving formats, ffmpeg warming up) the row says
*Downloading the clip* and the bar spins, instead of parking a determined bar at
zero.

**An end past the end of the video.** If the clip range runs past the video,
yt-dlp quietly clamps it. The percentage is now measured against the range
yt-dlp actually fetched, so it still reaches 100% instead of crawling towards an
end that does not exist.

## Notes

- Cutting a clip forces a keyframe at each end, so ffmpeg re-encodes the
  section — roughly 1× realtime on 1080p60 footage. That is what makes a clip
  take as long as it does; the bar now shows where it is rather than sitting at
  zero.
- A clip with no end (start filled in, end left blank) has no known length, so
  its bar spins for the whole fetch instead of showing a percentage.
- Full downloads are untouched: they already reported progress from yt-dlp
  directly.
- Nothing about the clip itself changed — the same range, the same
  frame-accurate cuts, the same file.

## How to get it

Run `ytgrab update`, or install this bundle.
