# ytgrab 0.3.0

Downloads now run in their own desktop window, and ytgrab can keep itself up to
date from the command line.

## What's new

- **A queue window that outlives the browser.** Clicking download no longer ties
  a job to the popup. ytgrab opens a small Windows window that owns the queue,
  shows live progress, and keeps downloading when you close the popup -- or
  Firefox itself. Closing the window keeps it running in the background; use
  Quit (or Ctrl-Q) to stop, and anything unfinished resumes the next time the
  queue starts.

- **A command-line tool, `ytgrab`.** It ships alongside the helper and the
  installer puts it on your PATH:

  - `ytgrab update` -- check GitHub for a newer release, download it, verify
    its checksum, install it, and print what changed.
  - `ytgrab update --check` -- just report whether a newer version exists.
  - `ytgrab notes` -- (re)print the release notes for the version you have.
  - `ytgrab version` -- print the installed versions and folders.
  - `ytgrab ui` -- open, or focus, the download queue window.

- **Automatic extension updates.** The add-on now declares an `update_url`, so
  Firefox updates it the same way it updates any other add-on. `ytgrab update`
  is only needed for the local helper.

- **Checksummed updates.** Every release publishes `SHA256SUMS.txt`, and
  `ytgrab update` verifies the bundle before it installs anything.

- **One document for the notes.** The file you are reading is added in the
  feature pull request, attached as the body of the GitHub release, copied into
  the download bundle as `RELEASE-NOTES.md`, and printed by `ytgrab update` --
  so "what changed" is maintained in exactly one place.

## How to use it

Nothing changes if you do nothing: downloads run in the queue window exactly as
before. To update later, open a new terminal and run:

    ytgrab update

It prints what it is about to install and asks before changing anything; add
`--yes` to skip the prompt. If a download is running it will be stopped and
resumed after the update, because the helper files have to be replaced.

## Under the hood

- The helper was split into a shared core (`ytgrab_core.py`), the loopback IPC
  layer (`ytgrab_ipc.py`), the queue window (`ytgrab_ui.py`) and the
  native-messaging bridge (`ytgrab_host.py`).
- Two executables are built from that source: `ytgrab-host.exe` (windowless:
  the Firefox helper and the queue window) and `ytgrab.exe` (the console CLI).
  The version string lives in one place and CI keeps it in step with the
  extension manifest.
